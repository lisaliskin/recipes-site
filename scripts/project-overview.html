база данных 04

структура базы данных

Нормализованная схема: продукты хранятся без дублей в справочнике products, ингредиенты рецепта — в связующей таблице recipe_ingredients с граммовкой. Калории считаются автоматически на клиенте.

таблица recipes

полетипописание
idINTEGER PKАвтоинкремент
titleVARCHARНазвание рецепта (напр. "Овсяная каша")
slugVARCHAR UNIQUEURL-идентификатор (напр. "ovsyanaya-kasha")
sectionVARCHARРаздел: завтраки / основное / перекусы / напитки / сладкое
descriptionTEXTКраткое описание блюда
servingsINTEGERКоличество порций по умолчанию
cooking_time_minutesINTEGERВремя приготовления в минутах
photoUUID → directus_filesФото блюда (загружается в Directus)

таблица products (справочник)

полетипописание
idINTEGER PKАвтоинкремент
nameVARCHAR UNIQUEНазвание продукта без дублей (напр. "молоко")
base_unitVARCHARЕдиница измерения: г / мл / шт
kcal_per_100gREALКалорийность на 100г/мл
protein / fat / carbsREALБелки, жиры, углеводы на 100г

таблица recipe_ingredients (связующая)

полетипописание
idINTEGER PKАвтоинкремент
recipe_idFK → recipes ON DELETE CASCADEСсылка на рецепт
product_idFK → productsСсылка на продукт из справочника
amountREALКоличество в base_unit (напр. 200 = 200г)
sortINTEGERПорядок отображения

таблица steps

полетипописание
idINTEGER PKАвтоинкремент
recipe_idFK → recipes ON DELETE CASCADEСсылка на рецепт
textTEXTТекст шага приготовления
sortINTEGERПорядок шага

Примечание по CASCADE: Таблицы steps и recipe_ingredients имеют ON DELETE CASCADE — при удалении рецепта все связанные шаги и ингредиенты удаляются автоматически.

функциональность 05

реализованные фичи

21 рецепт в пяти разделах с полным набором функций: поиск, избранное, масштабирование порций, список продуктов, офлайн-режим.

🗂
Разделы рецептов
Пять категорий: завтраки, основное, перекусы, напитки, сладкое. Цветовое оформление страницы меняется в зависимости от открытого раздела.
⚖️
Масштабирование порций
Два режима: по количеству порций (увеличить/уменьшить × N) и по конкретному ингредиенту (например, "у меня 300г гречки" — всё пересчитается автоматически). Composable useIngredientScaling.
🔥
Автоматический подсчёт калорий
Калорийность на порцию считается реактивно из БД: Σ(amount × kcal_per_100g / 100) / servings. Обновляется при изменении масштаба порций. Composable useCalories.
🛒
Список продуктов
Добавляй рецепты в список — ингредиенты автоматически объединяются без дублей с суммированием количеств. Шторка выезжает справа. Можно изменить порции перед добавлением.
❤️
Избранное
Сохраняется в localStorage — без авторизации и без бэкенда. Сердечко на карточке рецепта.
🌙
Тёмная / светлая тема
Переключатель в хедере. Сохраняется в localStorage. Плавный переход через CSS-переменные.
📱
PWA + офлайн-режим
Устанавливается как приложение на телефон или десктоп. Service Worker кэширует статику и рецепты — работает без интернета. Иконки и splash screen.
📐
Адаптивная вёрстка
Сетка перестраивается на мобильных. Шапка и карточки оптимизированы под touch-интерфейс.
⚙️
Headless CMS (Directus)
Добавлять/редактировать рецепты можно через визуальный интерфейс Directus — без кода. Нормализованная БД с справочником продуктов исключает дубликаты.

directus — как управлять рецептами

Войти в CMS
Открыть 157-180-79-150.sslip.io → войти с кредами → раздел Content
Добавить рецепт
Content → Recipes → + Create Item. Заполнить поля, добавить ингредиенты из справочника Products, добавить шаги.
Обновить сайт
После сохранения в Directus — данные сразу доступны через API. Сайт подтянет их при следующей загрузке страницы.

важные решения при разработке

sslip.io HTTPS без домена Сервис превращает IP в поддомен для Let's Encrypt — бесплатно без покупки домена
4 запроса Вместо вложенных полей Directus 11 не поддерживает wildcard в правах. Решение: отдельные запросы + join на клиенте
ON DELETE CASCADE Удаление рецептов SQLite таблицы пересозданы с каскадным удалением — при удалении рецепта убираются и ингредиенты, и шаги
ComputedRef<Recipe> Реактивность калорий useCalories принимает реактивный ref вместо plain объекта — пересчитывается когда рецепт загрузится из API
